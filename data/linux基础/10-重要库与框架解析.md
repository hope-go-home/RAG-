# 第 10 章：重要库与框架解析

## 10.1 什么是库？什么是框架？

### 库（Library）

库是**可以被程序调用的、预先写好的代码集合**。

```
没有库：
你写 Web 服务器 → 需要自己实现 TCP 协议
                 → 需要自己实现 HTTP 解析
                 → 需要自己实现 SSL/TLS
                 → 需要自己实现...

有库：
你写 Web 服务器 → 调用 libc → TCP 通信
                 → 调用 libcurl → HTTP 处理
                 → 调用 OpenSSL → HTTPS
                 → 调用 libpthread → 多线程
                 → 专注于业务逻辑
```

### 框架（Framework）

框架是**一套完整的"骨架"**，你往里面填代码。

```
库：你调用库
    程序 → 调用 → 库函数

框架：框架调用你
    框架 → 调用 → 你的代码（回调/钩子）
    你按照框架的规则写代码
```

**"好莱坞原则"（Don't call us, we'll call you）**：
- 使用库：你决定什么时候调用库函数
- 使用框架：框架决定什么时候调用你的代码

## 10.2 ⚡ glibc — GNU C 标准库

glibc 是 Linux 上**最核心的库**，几乎所有程序都依赖它。

### glibc 提供了什么？

```c
// 字符串处理
strlen(), strcpy(), strcmp(), sprintf()...

// 内存管理
malloc(), free(), calloc(), realloc()...

// 文件 I/O
fopen(), fread(), fwrite(), fclose()...
// 底层：open(), read(), write()...（系统调用包装）

// 进程管理
fork(), exec(), wait(), exit()...

// 信号
signal(), sigaction(), kill()...

// 数学
sin(), cos(), sqrt(), pow()...

// 时间和日期
time(), localtime(), strftime()...

// 网络
socket(), bind(), listen(), accept(), connect()...

// 国际化
setlocale(), iconv()...

// 线程（NPTL）
pthread_create(), pthread_mutex_lock()...
```

### glibc 的结构

```
glibc
├── libc.so.6    ← 核心 C 库（几乎所有功能）
├── libm.so.6    ← 数学库（数学函数）
├── libpthread.so.0  ← 线程库（POSIX 线程）
├── libdl.so.2   ← 动态加载（dlopen 等）
├── librt.so.1   ← 实时扩展（定时器、信号量）
├── libcrypt.so.1 ← 加密（已被 libxcrypt 替代）
└── libnss_*.so  ← 名字服务（DNS、用户等）
```

### ⚡ 系统调用包装

glibc 的很多函数就是系统调用的"包装"：

```c
// 你写的代码
int fd = open("file.txt", O_RDONLY);

// glibc 中的 open 函数
long open(const char *path, int flags) {
    // 1. 设置系统调用号
    // 2. 将参数存入寄存器
    // 3. 执行 syscall 指令
    // 4. 处理返回值
    // 5. 如果出错，设置 errno
    return syscall(SYS_open, path, flags);
}

// syscall 是一个内联函数，实际会执行：
// mov $2, %rax      ← 系统调用号 (SYS_open = 2)
// syscall            ← 切换到内核态
```

### errno — 错误处理机制

```c
#include <stdio.h>
#include <errno.h>
#include <string.h>

int main() {
    FILE *f = fopen("/nonexistent", "r");
    if (f == NULL) {
        printf("errno = %d\n", errno);         // 2
        printf("错误信息: %s\n", strerror(errno));  // "No such file or directory"
        perror("fopen");        // 自动输出 "fopen: No such file or directory"
    }
    return 0;
}
```

## 10.3 libpthread — POSIX 线程库

### 进程 vs 线程

```
进程：
┌────────────────────┐
│  代码段            │
│  数据段            │
│  堆                │
│  栈 (独立)          │  ← 每个进程有自己的栈
│  文件描述符表       │
│  进程 ID           │
└────────────────────┘
进程之间是隔离的，通信需要 IPC

线程：
┌────────────────────┐
│  代码段            │  ← 共享
│  数据段            │  ← 共享
│  堆                │  ← 共享
├── 线程 1 的栈 ─────┤
├── 线程 2 的栈 ─────┤  ← 每个线程有自己的栈
├── 线程 3 的栈 ─────┤
│  文件描述符表       │  ← 共享
│  线程 ID           │
└────────────────────┘
同一进程的线程共享大部分资源
```

### 创建线程

```c
#include <pthread.h>
#include <stdio.h>
#include <unistd.h>

void* worker(void* arg) {
    int id = *(int*)arg;
    printf("线程 %d 开始工作\n", id);
    sleep(1);
    printf("线程 %d 完成工作\n", id);
    return NULL;
}

int main() {
    pthread_t threads[3];
    int ids[3] = {1, 2, 3};
    
    // 创建 3 个线程
    for (int i = 0; i < 3; i++) {
        pthread_create(&threads[i], NULL, worker, &ids[i]);
    }
    
    // 等待所有线程结束
    for (int i = 0; i < 3; i++) {
        pthread_join(threads[i], NULL);
        printf("线程 %d 已回收\n", i + 1);
    }
    
    printf("所有线程完成\n");
    return 0;
}
```

### 线程同步

```c
#include <pthread.h>
#include <stdio.h>

int counter = 0;
pthread_mutex_t mutex = PTHREAD_MUTEX_INITIALIZER;

void* increment(void* arg) {
    for (int i = 0; i < 1000000; i++) {
        pthread_mutex_lock(&mutex);    // 加锁
        counter++;                      // 临界区
        pthread_mutex_unlock(&mutex);  // 解锁
    }
    return NULL;
}

int main() {
    pthread_t t1, t2;
    
    pthread_create(&t1, NULL, increment, NULL);
    pthread_create(&t2, NULL, increment, NULL);
    
    pthread_join(t1, NULL);
    pthread_join(t2, NULL);
    
    printf("counter = %d (期望: 2000000)\n", counter);
    
    pthread_mutex_destroy(&mutex);
    return 0;
}
```

**不加锁的问题**：
```
线程 1: counter = 50 → 读取 → 计算 counter+1
线程 2: counter = 50 → 读取 → 计算 counter+1
线程 1: 写回 counter = 51
线程 2: 写回 counter = 51  ← 覆盖了线程 1 的结果！
```
这叫**竞争条件（Race Condition）**。

## 10.4 OpenSSL — 加密通信库

### 核心功能

```c
#include <openssl/ssl.h>
#include <openssl/err.h>
#include <openssl/evp.h>
#include <openssl/sha.h>
#include <openssl/rand.h>
```

### 哈希（SHA-256）

```c
#include <openssl/evp.h>
#include <stdio.h>
#include <string.h>

int main() {
    EVP_MD_CTX *ctx = EVP_MD_CTX_new();
    
    unsigned char digest[EVP_MAX_MD_SIZE];
    unsigned int digest_len;
    
    EVP_DigestInit_ex(ctx, EVP_sha256(), NULL);
    EVP_DigestUpdate(ctx, "Hello, Linux!", 13);
    EVP_DigestFinal_ex(ctx, digest, &digest_len);
    
    printf("SHA-256: ");
    for (int i = 0; i < digest_len; i++) {
        printf("%02x", digest[i]);
    }
    printf("\n");
    
    EVP_MD_CTX_free(ctx);
    return 0;
}
```

### SSL/TLS 通信

```c
// 简化示例：HTTPS 客户端
#include <openssl/ssl.h>
#include <openssl/err.h>
#include <sys/socket.h>
#include <netdb.h>

int main() {
    // 初始化 SSL
    SSL_library_init();
    SSL_CTX *ctx = SSL_CTX_new(TLS_client_method());
    
    // 创建 TCP 连接
    int sock = socket(AF_INET, SOCK_STREAM, 0);
    struct hostent *host = gethostbyname("example.com");
    struct sockaddr_in addr;
    // ... 连接 ...
    
    // 将 SSL 套在 TCP 上
    SSL *ssl = SSL_new(ctx);
    SSL_set_fd(ssl, sock);
    SSL_connect(ssl);
    
    // 通过加密通道发送 HTTP 请求
    SSL_write(ssl, "GET / HTTP/1.1\r\nHost: example.com\r\n\r\n", 40);
    
    // 读取响应
    char buf[4096];
    SSL_read(ssl, buf, sizeof(buf));
    printf("%s\n", buf);
    
    // 清理
    SSL_free(ssl);
    SSL_CTX_free(ctx);
    close(sock);
    
    return 0;
}
```

## 10.5 libcurl — 网络传输库

### 基本用法

```c
#include <curl/curl.h>
#include <stdio.h>

// 回调函数：处理接收到的数据
size_t write_callback(void *data, size_t size, size_t nmemb, void *userp) {
    FILE *fp = (FILE*)userp;
    return fwrite(data, size, nmemb, fp);
}

int main() {
    CURL *curl = curl_easy_init();
    
    if (curl) {
        FILE *fp = fopen("page.html", "w");
        
        // 设置 URL
        curl_easy_setopt(curl, CURLOPT_URL, "https://example.com");
        
        // 设置写回调
        curl_easy_setopt(curl, CURLOPT_WRITEFUNCTION, write_callback);
        curl_easy_setopt(curl, CURLOPT_WRITEDATA, fp);
        
        // 忽略 SSL 证书验证（仅测试）
        // curl_easy_setopt(curl, CURLOPT_SSL_VERIFYPEER, 0L);
        
        // 执行请求
        CURLcode res = curl_easy_perform(curl);
        
        if (res != CURLE_OK) {
            fprintf(stderr, "请求失败: %s\n", curl_easy_strerror(res));
        }
        
        curl_easy_cleanup(curl);
        fclose(fp);
    }
    
    return 0;
}
```

## 10.6 框架概念解析

### 为什么需要框架？

```
没有框架：
- 你写 Web 服务 → 自己处理 TCP 连接
- 自己解析 HTTP 请求
- 自己管理路由
- 自己处理 Session/Cookie
- 自己处理模板渲染
- 自己处理数据库连接
- ...

有框架 (如 Flask/Express/Django)：
- 路由：@app.get('/user/<id>')
- 请求：request.json['name']
- 响应：return jsonify({'ok': true})
- 模板：render_template('index.html')
- 数据库：ORM 框架自动处理
```

### 框架的核心思想

1. **控制反转 (IoC)** — 框架控制程序流程
2. **依赖注入 (DI)** — 框架自动提供依赖
3. **约定优于配置** — 按约定命名，减少配置
4. **DRY (Don't Repeat Yourself)** — 消除重复代码
5. **中间件 (Middleware)** — 请求/响应的处理链

### Web 框架的例子

**Flask（Python）**：
```python
from flask import Flask, jsonify, request

app = Flask(__name__)

@app.route('/api/user/<int:id>', methods=['GET'])
def get_user(id):
    # Flask 自动解析 URL、处理路由
    # request 自动封装 HTTP 请求数据
    return jsonify({"id": id, "name": "Alice"})

@app.route('/api/user', methods=['POST'])
def create_user():
    data = request.get_json()
    # 处理数据...
    return jsonify({"status": "ok"}), 201

if __name__ == '__main__':
    app.run(debug=True)
```

**Express（Node.js）**：
```javascript
const express = require('express');
const app = express();

app.get('/api/user/:id', (req, res) => {
    res.json({ id: req.params.id, name: 'Alice' });
});

app.post('/api/user', (req, res) => {
    // req.body 自动解析请求体
    res.status(201).json({ status: 'ok' });
});

app.listen(3000);
```

### ⚡ Web 框架的工作原理

```
客户端请求
    ↓
HTTP 服务器（如 Gunicorn/Nginx）
    ↓
WSGI/ASGI 接口
    ↓
框架中间件链
    ├── 日志中间件 → 记录请求
    ├── 认证中间件 → 检查登录
    ├── Session 中间件 → 解析 Session
    ├── CSRF 防护
    └── 路由中间件 → 匹配 URL → 调用你的处理函数
         ↓
你的处理函数 (如 get_user)
         ↓
返回响应 → 经过中间件链返回
         ↓
HTTP 响应发送给客户端
```
