# 第 9 章：包管理原理

## 9.1 什么是包管理？

### 没有包管理器的日子

想象一下你要安装一个软件：
```
1. 去官网下载源码
2. 解压
3. 阅读 INSTALL 文档
4. 安装依赖库 A、B、C
5. 安装 A 需要先安装 X、Y
6. 安装 B 需要特定版本的 Z...
7. 编译报错 → 缺少 xxx-dev
8. 安装 xxx-dev...
9. 再次编译 → 又报错
10. ... 折腾半天，终于装好了
```

这就是**依赖地狱**。

### 包管理器解决了什么？

```
包管理器 (apt/dnf/pacman)
    ↓
你执行：apt install nginx
    ↓
包管理器自动：
    1. 查询 nginx 的依赖列表
    2. 下载 nginx 及其所有依赖（openssl、zlib、pcre...）
    3. 校验文件完整性
    4. 安装所有包到正确的位置
    5. 运行安装后脚本
    6. 更新数据库
    ↓
完成！一切都是自动的
```

## 9.2 ⚡ 包的核心概念

### 什么是包（Package）

一个包 = 软件的**打包格式**，包含：

```
mypackage_1.0-1.deb
│
├── control       ← 元数据（包名、版本、依赖、描述）
├── data.tar.gz   ← 实际文件（二进制、配置文件、文档）
│   ├── usr/bin/mytool
│   ├── etc/mypackage/config.conf
│   └── usr/share/doc/...
├── preinst       ← 安装前脚本
├── postinst      ← 安装后脚本
├── prerm         ← 卸载前脚本
└── postrm        ← 卸载后脚本
```

### 包的元数据（control 文件）

```
Package: nginx
Version: 1.18.0-6ubuntu1
Architecture: amd64
Maintainer: Ubuntu Developers
Description: high performance web server
Depends: libc6 (>= 2.28), libpcre3, zlib1g, openssl
Recommends: nginx-doc
Suggests: nginx-extras
Conflicts: apache2 (<< 2.4)
Replaces: nginx-core
```

**依赖关系**：
- Depends — 必须安装的依赖
- Recommends — 推荐的软件包（通常一起装）
- Suggests — 可选的建议软件包
- Conflicts — 冲突的软件包（不能同时安装）
- Replaces — 替换的软件包
- Provides — 提供的虚拟包（如 "mail-server"）

### 版本号规则

```
主版本号.次版本号.修订号-打包号
   ↑        ↑       ↑      ↑
大改动    新功能    bug修复  发行版打包

1.18.0-6ubuntu1
↑  ↑  ↑ ↑    ↑
主 次 修 发行版序号
```

## 9.3 Debian 包管理（dpkg + apt）

### dpkg — 底层包工具

```bash
# 安装本地 .deb 文件
sudo dpkg -i package.deb        # -i = install
dpkg -i package.deb --force-depends  # 忽略依赖强制安装

# 卸载
sudo dpkg -r package            # -r = remove（保留配置文件）
sudo dpkg -P package            # -P = purge（完全清除）

# 查询
dpkg -l                         # 列出所有已安装的包
dpkg -l | grep nginx            # 查找已安装的 nginx
dpkg -L nginx                   # 列出 nginx 安装的所有文件
dpkg -S /etc/nginx/nginx.conf   # 查询文件属于哪个包
dpkg -s nginx                   # 查看包的详细信息
dpkg -c package.deb             # 查看 .deb 包中的内容

# 验证
dpkg --verify                   # 检查已安装包的文件完整性
```

**dpkg 的数据库**：
```
/var/lib/dpkg/
├── available      ← 所有可用包的信息
├── status         ← 已安装包的状态
├── info/          ← 每个包的详细信息
│   ├── nginx.list     ← nginx 安装的文件列表
│   ├── nginx.md5sums  ← 文件校验和
│   └── nginx.postinst ← 安装后脚本
└── updates/       ← 更新信息
```

### apt — 高级包工具

```bash
# 更新包索引（从软件源读取最新包列表）
sudo apt update                  # 核心！必须先更新

# 安装
sudo apt install nginx           # 安装（自动处理依赖）
sudo apt install nginx=1.18.0    # 安装特定版本
sudo apt install ./package.deb   # 安装本地包（自动处理依赖）

# 卸载
sudo apt remove nginx            # 移除（保留配置文件）
sudo apt purge nginx             # 彻底移除
sudo apt autoremove              # 移除不再需要的依赖

# 更新
sudo apt upgrade                 # 升级所有包（不删除已安装的）
sudo apt full-upgrade            # 升级（会处理依赖变更）
sudo apt dist-upgrade            # 发行版升级

# 搜索
apt search nginx                 # 搜索包名或描述
apt show nginx                   # 显示包详细信息
apt policy nginx                 # 查看可用版本

# 清理
sudo apt clean                   # 清空下载的 .deb 缓存
sudo apt autoclean               # 清空已过期的 .deb
```

### ⚡ apt 的工作原理

```
apt update
    ↓
读取 /etc/apt/sources.list 和 /etc/apt/sources.list.d/*.list
    ↓
连接软件源（如 http://archive.ubuntu.com/ubuntu）
    ↓
下载 Packages.gz（包索引文件，压缩格式）
    ↓
解压并更新本地数据库 /var/lib/apt/lists/
    ↓
现在 apt 知道了所有可用的包和版本

apt install nginx
    ↓
查询本地数据库，找到 nginx 及其依赖
    ↓
检查软件包签名（GPG 校验）
    ↓
下载 .deb 文件到 /var/cache/apt/archives/
    ↓
调用 dpkg -i 安装
    ↓
运行安装后脚本
    ↓
标记为已安装
```

### 软件源配置

```bash
# /etc/apt/sources.list
deb http://archive.ubuntu.com/ubuntu focal main restricted universe multiverse
deb-src http://archive.ubuntu.com/ubuntu focal main restricted universe multiverse

# 格式：
# deb    = 二进制包
# deb-src = 源码包
# URL    = 仓库地址
# 发行版 = focal (Ubuntu 20.04)
# 组件   = main/restricted/universe/multiverse
```

**组件说明**：
```
main        — Ubuntu 官方支持的开源软件
restricted  — 官方支持的非自由软件（如驱动）
universe    — 社区维护的软件
multiverse  — 非自由软件
```

## 9.4 Red Hat 包管理（rpm + dnf/yum）

### rpm — 底层包工具

```bash
# 安装
sudo rpm -ivh package.rpm        # -i install, -v verbose, -h hash

# 卸载
sudo rpm -e package              # -e erase

# 查询
rpm -qa                         # 所有已安装的包
rpm -ql nginx                   # 包的文件列表
rpm -qf /etc/nginx/nginx.conf   # 文件属于哪个包
rpm -qi nginx                   # 包信息
```

### dnf — 高级包工具（Fedora/RHEL 8+）

```bash
dnf install nginx               # 安装
dnf remove nginx                # 卸载
dnf update nginx                # 更新
dnf search nginx                # 搜索
dnf info nginx                  # 信息
dnf provides /etc/nginx/nginx.conf  # 查找文件属于哪个包
dnf groupinstall "Web Server"   # 安装包组
dnf autoremove                  # 清理不需要的依赖
```

### yum — 传统工具（RHEL 7 及之前）

```bash
yum install nginx
yum remove nginx
yum update
yum search nginx
yum list installed
```

## 9.5 从源码编译安装

有时包管理器没有你需要的软件或版本，需要从源码编译。

### 典型流程

```bash
# 1. 下载源码
wget https://example.com/software-1.0.tar.gz

# 2. 解压
tar -xzf software-1.0.tar.gz
cd software-1.0/

# 3. 配置（检测系统环境，生成 Makefile）
./configure --prefix=/usr/local

# 4. 编译
make -j$(nproc)                 # -j 并行编译

# 5. 安装
sudo make install
```

### ⚡ ./configure 到底在做什么？

```
./configure --prefix=/usr/local --enable-ssl
    ↓
1. 检查编译器（gcc 是否存在？版本够吗？）
2. 检查头文件（有没有 openssl/ssl.h？）
3. 检查库文件（有没有 libssl.so？）
4. 检查函数是否存在（有没有 pthread_create？）
5. 根据检查结果生成 Makefile
6. 生成 config.h（定义宏）

如果检查失败 → 提示缺少的依赖
如果检查通过 → 生成 Makefile，准备编译
```

### ⚡ Make 和 Makefile

Makefile 是**编译规则文件**，告诉 make 怎么编译：

```makefile
# 简单的 Makefile
CC = gcc
CFLAGS = -Wall -O2
LDFLAGS = -lm

# 目标: 依赖
program: main.o utils.o
	$(CC) -o program main.o utils.o $(LDFLAGS)

main.o: main.c header.h
	$(CC) $(CFLAGS) -c main.c

utils.o: utils.c header.h
	$(CC) $(CFLAGS) -c utils.c

clean:
	rm -f *.o program

install:
	cp program /usr/local/bin/
```

**make 的原理**：
```
make program
    ↓
检查 program 是否存在
    ├── 不存在 → 执行命令
    ├── 存在 → 检查依赖是否更新
    │   ├── main.o 比 main.c 旧？→ 重新编译 main.o
    │   ├── utils.o 比 utils.c 旧？→ 重新编译 utils.o
    │   └── 都最新 → "make: 'program' is up to date."
    └── 重新链接 program
```

### CMake — 跨平台的构建系统

```cmake
# CMakeLists.txt
cmake_minimum_required(VERSION 3.10)
project(MyProject)

set(CMAKE_C_STANDARD 11)

# 查找依赖库
find_package(OpenSSL REQUIRED)

# 添加可执行文件
add_executable(myapp main.c utils.c)

# 链接库
target_link_libraries(myapp OpenSSL::SSL OpenSSL::Crypto)

# 安装
install(TARGETS myapp DESTINATION bin)
```

```bash
# CMake 的典型构建流程
mkdir build && cd build
cmake ..                    # 配置（检测系统，生成 Makefile）
cmake --build . -j$(nproc)  # 编译
sudo cmake --install .      # 安装
```

### Autotools — 传统的构建系统

```bash
# 如果项目没有 configure 文件，需要先生成
autoreconf -i                # 生成 configure 脚本

./configure                  # 配置
make                        # 编译
sudo make install           # 安装
```

## 9.6 库文件管理

### 静态库 vs 动态库

| | 静态库 (.a) | 动态库 (.so) |
|---|---|---|
| 链接时机 | 编译时 | 运行时 |
| 文件大小 | 可执行文件大 | 可执行文件小 |
| 内存使用 | 每个程序一份 | 共享内存 |
| 更新 | 需要重新链接 | 替换 .so 即可 |
| 依赖 | 无运行时依赖 | 需确保 .so 存在 |

### 库的搜索路径

```bash
# 编译时的库搜索路径
gcc -L/usr/local/lib -lmylib program.c

# 运行时的库搜索路径
1. LD_LIBRARY_PATH 环境变量
2. /etc/ld.so.conf 中配置的路径
3. /lib 和 /usr/lib
4. /usr/local/lib

# 查看程序依赖的动态库
ldd /usr/bin/nginx
# linux-vdso.so.1 (0x00007ffe...)
# libc.so.6 => /lib/x86_64-linux-gnu/libc.so.6
# libpcre.so.3 => /lib/x86_64-linux-gnu/libpcre.so.3

# 更新库缓存
sudo ldconfig                 # 读取 /etc/ld.so.conf，更新 /etc/ld.so.cache

# 查看缓存中的库
ldconfig -p | grep nginx

# 添加自定义库路径
echo "/usr/local/lib" | sudo tee /etc/ld.so.conf.d/local.conf
sudo ldconfig
```

## 9.7 容器化与包管理

### 容器的思想

```
传统部署：
你的程序 + 依赖库 → 安装在宿主系统上
问题：不同程序可能依赖不同版本的库

容器：
你的程序 + 依赖库 → 打包成一个镜像
镜像完全自包含 → 在任何 Linux 上都能运行
```

### Docker 与包管理

```dockerfile
# Dockerfile
FROM ubuntu:20.04              # 基础镜像（最小化的 Ubuntu）

RUN apt update && apt install -y \
    nginx \
    openssl \
    && rm -rf /var/lib/apt/lists/*    # 清理缓存（减小镜像体积）

COPY myapp.conf /etc/nginx/conf.d/

EXPOSE 80

CMD ["nginx", "-g", "daemon off;"]
```

### Flatpak / Snap / AppImage

现代 Linux 的"应用级包管理"：

| 工具 | 特点 |
|---|---|
| Snap | Canonical 开发，沙箱隔离，自动更新 |
| Flatpak | 专注于桌面应用，沙箱，跨发行版 |
| AppImage | 单文件，下载即用，无需安装 |

## 🔧 动手练习

```bash
# 1. 探索包管理
apt update                      # 更新包索引
apt search "web server"         # 搜索 Web 服务器
apt show nginx                  # 查看 nginx 包信息
apt depends nginx               # 查看 nginx 的依赖
dpkg -L nginx | head -20        # 查看 nginx 安装的文件

# 2. 从源码编译一个软件
sudo apt install build-essential checkinstall
wget http://example.com/hello-1.0.tar.gz
tar -xzf hello-1.0.tar.gz
cd hello-1.0/
./configure
make
sudo make install

# 3. 查看依赖
ldd /bin/ls                     # 查看 ls 依赖的库
ldconfig -p | grep libc         # 查看系统中的 libc

# 4. 制作自己的 deb 包
# 用 checkinstall 替代 make install
sudo checkinstall
# 会生成一个 .deb 包，下次可以直接 dpkg -i
```
