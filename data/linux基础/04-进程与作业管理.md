# 第 4 章：进程与作业管理

## 4.1 什么是进程？

### 程序 vs 进程

| | 程序 (Program) | 进程 (Process) |
|---|---|---|
| 本质 | 硬盘上的文件（二进制代码） | 内存中正在运行的程序 |
| 状态 | 静态 | 动态 |
| 比喻 | 菜谱 | 正在做菜的过程 |
| 生命周期 | 永久存在 | 创建→运行→销毁 |

### ⚡ 进程的组成

一个进程在内存中包含：

```
┌─────────────────────────┐
│        栈 (Stack)        │  ← 局部变量、函数调用
├─────────────────────────┤
│        堆 (Heap)         │  ← 动态分配的内存 (malloc)
├─────────────────────────┤
│     数据段 (Data)        │  ← 全局变量、静态变量
├─────────────────────────┤
│     代码段 (Text)        │  ← 程序指令（只读）
└─────────────────────────┘
```

### ⚡ PCB — 进程控制块

内核为每个进程维护一个 **PCB（Process Control Block）**，包含：

```c
// 这是概念模型，不是实际代码
struct task_struct {      // Linux 中的 PCB 结构
    pid_t pid;            // 进程 ID（唯一标识）
    pid_t ppid;           // 父进程 ID
    
    // 状态
    volatile long state;  // 运行、睡眠、停止等
    
    // 资源
    struct files_struct *files;     // 打开的文件
    struct mm_struct *mm;           // 内存信息
    struct signal_struct *signal;   // 信号
    
    // 调度
    int priority;         // 优先级
    unsigned int time_slice;        // 时间片
    
    // ... 几百个字段
};
```

## 4.2 进程的状态

```
                    ┌──────────┐
                    │  创建    │
                    │ (New)    │
                    └────┬─────┘
                         ↓
    ┌──────────┐    ┌──────────┐
    │  就绪态  │ ←─ │  运行态  │
    │ (Ready)  │ ──→│ (Running)│
    └──────────┘    └────┬─────┘
         ↑               ↓
         │          ┌──────────┐
         │          │  等待态  │  ← 等待 I/O、等待锁
         │          │ (Waiting)│
         │          └──────────┘
         ↓
    ┌──────────┐
    │  终止态  │
    │ (Terminated)│
    └──────────┘
```

```bash
# 用 ps 查看进程状态
ps aux
# STAT 列：
# R — Running (正在运行或可运行)
# S — Sleeping (可中断的睡眠，等待事件)
# D — Disk Sleep (不可中断睡眠，等待 I/O)
# Z — Zombie (僵尸进程)
# T — Stopped (被停止)
# + — 在前台进程组中
# s — 会话领导者
```

## 4.3 ⚡ 进程的一生

### fork() — 进程创建（最重要的系统调用）

```c
#include <stdio.h>
#include <unistd.h>

int main() {
    printf("父进程 PID: %d\n", getpid());
    
    pid_t pid = fork();   // ← 关键！创建子进程
    
    if (pid == 0) {
        // 这是子进程
        printf("子进程: 我的 PID = %d, 父进程 PID = %d\n", 
               getpid(), getppid());
    } else if (pid > 0) {
        // 这是父进程
        printf("父进程: 子进程的 PID = %d\n", pid);
    } else {
        // fork 失败
        perror("fork");
    }
    
    return 0;
}
```

**fork() 的魔法**：
```
fork() 被调用一次，返回两次！
        ↓
    ┌──────┐
    │ 进程A │   ← fork() 返回 1234 (子进程 PID)
    └──┬───┘
       │
  ┌────┴────┐
  │         │
  ↓         ↓
┌──────┐ ┌──────┐
│ 进程A │ │ 进程B │  ← fork() 返回 0
│(父进程)│ │(子进程)│
└──────┘ └──────┘
 内存：代码段共享、数据段复制（写时复制）
```

### exec() — 变身

```c
#include <unistd.h>

int main() {
    pid_t pid = fork();
    
    if (pid == 0) {
        // 子进程：把自己变成 ls
        execlp("ls", "ls", "-la", NULL);
        // 如果 exec 成功，不会执行到这里
        perror("exec 失败");
        return 1;
    }
    
    // 父进程等待子进程结束
    wait(NULL);
    printf("子进程已结束\n");
    return 0;
}
```

**fork + exec 的工作流程**：
```
Shell 输入 ls -la
    ↓
Shell 调用 fork()
    ↓
Shell（父）    子进程
 等待(wait)    子进程调用 exec("ls")
                子进程变成 ls
                ls 运行并退出
    ↓
Shell 继续接收输入
```

### wait() — 收尸

子进程结束后，必须由父进程调用 wait() 来"收尸"，否则子进程变成**僵尸**。

```bash
# 查看僵尸进程
ps aux | grep Z

# 僵尸进程的特征：STAT=Z，且不占用资源
# 但 PCB 还在内核中（需要 wait 来回收）
```

### 孤儿进程 vs 僵尸进程

| | 孤儿进程 | 僵尸进程 |
|---|---|---|
| 定义 | 父进程先于子进程结束 | 子进程结束但父进程没 wait |
| 处理 | init (PID=1) 收养并 wait | 占用 PCB 资源 |
| 危害 | 无 | 大量僵尸会耗尽进程表 |

## 4.5 进程优先级

### nice 值范围：-20 到 +19

- 数字越小 → 优先级越高
- 默认 nice = 0
- 普通用户只能降低优先级（调大 nice）

```bash
# 以低优先级运行
nice -n 10 ./slow_program

# 修改运行中进程的优先级
renice -n -5 -p 1234      # root 可以提升优先级
renice -n 10 -p 1234      # 降低优先级
```

### 实时进程

优先级更高的特殊进程：
```bash
chrt -f 99 ./realtime_prog   # FIFO 调度，优先级最高
```

## 4.6 ⚡ 信号（Signal）— 进程间的异步通知

信号是 Linux 中"软中断"，用来通知进程发生了某事件。

### 常用信号

| 信号 | 数值 | 含义 | 默认动作 |
|---|---|---|---|
| SIGHUP | 1 | 挂起（终端断开） | 终止 |
| SIGINT | 2 | 中断（Ctrl+C） | 终止 |
| SIGQUIT | 3 | 退出（Ctrl+\） | 终止+转储 |
| SIGKILL | 9 | 强制杀死（不能被忽略） | 终止 |
| SIGTERM | 15 | 优雅终止（默认） | 终止 |
| SIGSTOP | 19 | 停止（不能被忽略） | 停止 |
| SIGCONT | 18 | 继续运行 | 继续 |

### 发送信号

```bash
kill -15 1234          # 优雅终止 PID 1234
kill -SIGTERM 1234     # 同上
kill -9 1234           # 强制杀死（最后手段）
kill -2 1234           # 相当于 Ctrl+C
killall nginx          # 杀死所有 nginx 进程
pkill -9 -u alice     # 杀死 alice 的所有进程
```

### ⚡ 信号处理（从 C 角度看）

```c
#include <stdio.h>
#include <signal.h>
#include <unistd.h>

// 信号处理函数
void handle_sigint(int sig) {
    printf("\n收到 SIGINT (Ctrl+C)，但我不会退出！\n");
    printf("按 Ctrl+\ 才能强制退出\n");
}

int main() {
    // 注册信号处理函数
    signal(SIGINT, handle_sigint);
    
    while (1) {
        printf("工作中... PID = %d\n", getpid());
        sleep(1);
    }
    
    return 0;
}
```

**信号处理流程**：
```
内核检测到 Ctrl+C 被按下
    ↓
找到前台进程组
    ↓
发送 SIGINT 给进程
    ↓
进程收到信号
    ├─ 忽略（如果设置了 SIG_IGN）
    ├─ 执行自定义处理函数
    └─ 默认动作（终止进程）
```

## 4.7 作业控制（Job Control）

### 前台 vs 后台

```bash
# 运行前台进程
sleep 100

# 运行后台进程（末尾加 &）
sleep 100 &

# 把前台进程放到后台
# 先 Ctrl+Z 暂停
# 然后
bg                    # 放到后台继续运行

# 把后台进程放回前台
fg %1                 # 将作业 1 放到前台

# 查看作业
jobs
[1]+  Running                 sleep 100 &
[2]-  Running                 find / -name "*.txt" &
  ↑       ↑                            ↑
作业号   状态                        命令
```

### nohup — 退出终端后继续运行

```bash
# 普通后台：退出终端后会收到 SIGHUP → 进程终止
# nohup：忽略 SIGHUP，退出后继续运行
nohup long_running_task &

# 输出会写入 nohup.out
```

### ⚡ SIGHUP 的原理

当你退出终端时：
```
终端关闭
    ↓
内核发送 SIGHUP (信号 1) 给终端对应的 Shell
    ↓
Shell 将 SIGHUP 转发给所有子进程
    ↓
子进程收到 SIGHUP → 默认终止
```

```bash
# 解决方案 1：nohup（忽略 SIGHUP）
nohup command &

# 解决方案 2：disown（从 Shell 作业表中移除）
command &
disown

# 解决方案 3：tmux / screen（完全独立的会话）
tmux new -s mysession
# 运行你的命令
# Ctrl+B D 分离
# tmux attach -t mysession 重新连接
```

## 4.8 ⚡ /proc 文件系统 — 进程的窗口

`/proc` 是一个**伪文件系统**，不占硬盘空间，由内核动态生成。

```bash
# 查看进程 1 (init/systemd) 的信息
ls /proc/1/

# 重要文件
/proc/[pid]/cmdline     # 启动命令
/proc/[pid]/cwd         # 当前工作目录（符号链接）
/proc/[pid]/environ     # 环境变量
/proc/[pid]/exe         # 可执行文件（符号链接）
/proc/[pid]/fd/         # 打开的文件描述符
/proc/[pid]/maps        # 内存映射
/proc/[pid]/status      # 进程状态
/proc/[pid]/limits      # 资源限制
/proc/cpuinfo           # CPU 信息
/proc/meminfo           # 内存信息
/proc/loadavg           # 系统负载
/proc/uptime            # 运行时间
```

**实用例子**：
```bash
# 查看某个进程打开了哪些文件
ls -la /proc/1234/fd/

# 恢复误删的文件（前提是进程还在运行）
cp /proc/1234/fd/3 recovered_file

# 查看进程的完整命令行
cat /proc/1234/cmdline | tr '\0' ' '

# 查看进程的环境变量
cat /proc/1234/environ | tr '\0' '\n'
```

### /proc 的读取原理

```
当执行 cat /proc/1234/status 时：
    ↓
内核的 proc 文件系统驱动被调用
    ↓
从 task_struct (PCB) 中读取对应字段
    ↓
格式化为文本
    ↓
返回给用户程序
    ↓
你看到了进程的信息
```

## 4.9 systemd — 现代的 init 系统

`systemd` 是 PID 为 1 的进程，管理所有其他进程。

```bash
# 管理系统服务
systemctl status nginx     # 查看状态
systemctl start nginx      # 启动
systemctl stop nginx       # 停止
systemctl restart nginx    # 重启
systemctl enable nginx     # 开机自启
systemctl disable nginx    # 禁止开机自启

# 查看依赖关系
systemctl list-dependencies nginx

# 分析启动时间
systemd-analyze blame      # 各服务的启动耗时
```

### systemd 的 Unit 文件

```
/etc/systemd/system/        # 系统管理员配置
/usr/lib/systemd/system/    # 软件包自带的配置
```

例子 `/etc/systemd/system/myapp.service`：
```ini
[Unit]
Description=我的应用程序
After=network.target

[Service]
Type=simple
User=alice
WorkingDirectory=/opt/myapp
ExecStart=/usr/bin/python3 /opt/myapp/main.py
Restart=on-failure

[Install]
WantedBy=multi-user.target
```
