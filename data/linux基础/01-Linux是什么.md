# 第 1 章：Linux 是什么

## 1.1 计算机的"三要素"

在学习 Linux 之前，先搞懂一台计算机怎么工作：

```
应用程序 (浏览器、游戏、编辑器)
     ↓  调用
操作系统 (Windows/Linux/macOS)
     ↓  管理
硬件   (CPU、内存、硬盘、网卡)
```

- **硬件**：看得见摸得着的物理设备
- **操作系统**：介于硬件和应用之间的"大管家"
- **应用程序**：我们日常使用的软件

⚡ **操作系统的核心职责**：
1. 管理 CPU — 决定哪个程序用 CPU
2. 管理内存 — 分配和回收内存
3. 管理硬盘 — 文件系统的存取
4. 管理设备 — 键盘、鼠标、网卡
5. 提供接口 — 让程序员写代码时不直接操作硬件

## 1.2 Linux 的诞生故事

### Unix 时代（1969）
- 贝尔实验室的 Ken Thompson 和 Dennis Ritchie 发明了 Unix
- 这是现代操作系统的"祖宗"
- C 语言也是他们发明的（为了写 Unix）

### GNU 计划（1983）
- Richard Stallman 发起：要做一个**自由**的 Unix 系统
- GNU = GNU's Not Unix（递归缩写，程序员喜欢玩这种梗）
- 开发了大量工具：gcc（编译器）、emacs（编辑器）等
- **缺了一个内核**（操作系统的核心）

### Linux 诞生（1991）
- Linus Torvalds（林纳斯·托瓦兹），芬兰大学生
- 觉得当时的 Unix 系统太贵，自己写了一个内核
- 发布在新闻组，开源给全世界
- **Linux 内核 + GNU 工具 = 完整的操作系统**

### 为什么叫 Linux？
- Linus + Unix = Linux
- 吉祥物是一只叫 Tux 的企鹅（Linus 曾被企鹅咬过）

## 1.3 Linux 的核心哲学

### ⚡ 一切皆文件
这是 Linux 最最重要的思想：

```c
// 在 Linux 中，以下"东西"都被当作文件处理：
- 普通文件     → 文档、图片、视频
- 目录         → 文件夹
- 键盘输入     → /dev/input/...
- 屏幕输出     → /dev/tty
- 网络数据     → socket（套接字）
- 进程信息     → /proc/... 
- 硬件设备     → /dev/sda（硬盘）
```

**好处**：用同一套 API（open/read/write/close）操作所有东西

### 小即是美
- 每个工具只做一件事，把这件事做好
- 通过组合完成复杂任务

### 清晰和透明
- 系统的配置都是文本文件
- 没有"注册表"这种黑盒
- 你能看到一切，能修改一切

## 1.4 Linux 的架构（分层结构）

```
┌─────────────────────────────────────┐
│        用户应用程序                 │  ← 浏览器、VSCode、游戏
│    (User Applications)              │
├─────────────────────────────────────┤
│        系统工具/库                  │  ← Shell、编译器、系统库
│    (System Utilities/Libraries)     │
├─────────────────────────────────────┤
│        Linux 内核 (Kernel)          │  ← 操作系统的核心
│  ┌──────────┬──────────┬─────────┐  │
│  │ 进程管理 │ 内存管理 │ 文件系统 │  │
│  ├──────────┼──────────┼─────────┤  │
│  │ 设备驱动 │ 网络协议 │ 安全模块 │  │
│  └──────────┴──────────┴─────────┘  │
├─────────────────────────────────────┤
│           硬件 (Hardware)           │  ← CPU、内存、硬盘
└─────────────────────────────────────┘
```

### ⚡ 用户态 vs 内核态

这是最关键的概念之一：

| | 用户态 (User Mode) | 内核态 (Kernel Mode) |
|---|---|---|
| 权限 | 低 | 最高 |
| 能做什么 | 运行普通程序 | 操作硬件、管理内存 |
| 故障影响 | 只崩自己的进程 | 整个系统崩溃 |
| CPU 指令 | 受限指令集 | 所有指令 |

**工作流程**：
```
用户程序 (用户态)
    ↓ 调用 read() ← 这是一个"系统调用"
    ↓ 触发 0x80 中断 或 syscall 指令
    ↓ 切换到内核态
内核执行 read (内核态)
    ↓ 读取硬盘数据
    ↓ 返回给用户程序
    ↓ 切换回用户态
用户程序拿到数据
```

## 1.5 发行版（Distribution）

Linux 内核 + 各种软件包 = 发行版

### 主流发行版家族

```
Debian 家族           Red Hat 家族        Arch 家族
    │                     │                  │
├ Ubuntu（桌面）    ├ RHEL（企业）       ├ Arch（DIY）
├ Debian（稳定）    ├ CentOS/Rocky       ├ Manjaro（友好）
├ Linux Mint        ├ Fedora（前沿）      └ EndeavourOS
└ Kali（安全）      └ openSUSE
```

### 不同场景的选择

| 场景 | 推荐发行版 | 原因 |
|---|---|---|
| 学习入门 | Ubuntu / Linux Mint | 社区大、教程多、易用 |
| 服务器 | Ubuntu Server / Rocky Linux | 稳定、企业支持 |
| 开发 | Fedora / Ubuntu | 包比较新 |
| 嵌入式 | Yocto / Buildroot | 可定制 |
| 安全/黑客 | Kali Linux | 预装大量安全工具 |

### 包管理器差异

| 家族 | 包格式 | 包管理器 | 命令 |
|---|---|---|---|
| Debian | .deb | apt / dpkg | apt install xxx |
| Red Hat | .rpm | dnf / yum / rpm | dnf install xxx |
| Arch | .pkg.tar.zst | pacman | pacman -S xxx |

## 1.6 Shell — 与 Linux 对话的方式

### 什么是 Shell？

Shell 是"壳"，是用户和内核之间的翻译官：

```
你 (键盘输入)  
    ↓ 命令
Shell (bash/zsh)
    ↓ 解析执行
内核 (Kernel)
    ↓
硬件 (Hardware)
```

### 常见的 Shell

| Shell | 特点 |
|---|---|
| bash | 最主流，默认 |
| zsh | 功能丰富，oh-my-zsh |
| sh | 最基础，脚本兼容性最好 |
| fish | 开箱即用，自动提示 |

### 打开终端

在 Ubuntu 中：`Ctrl + Alt + T` 或 右键 → 打开终端

你会看到这样的提示符：
```
username@hostname:~$
```

解析：
- `username` — 当前用户名
- `hostname` — 计算机名
- `~` — 当前目录（~ 表示 home 目录）
- `$` — 普通用户（root 是 #）

## 1.7 你的第一个命令

```bash
# 打印 Hello World
echo "Hello, Linux!"

# 查看当前谁在登录
whoami

# 查看当前时间
date

# 查看日历
cal

# 查看系统信息
uname -a

# 查看已运行时间
uptime
```

### 命令的基本格式

```bash
command  [选项]  [参数]
   ↑       ↑       ↑
 命令名    --或-   操作对象
```

示例：
```bash
ls       # 只看命令
ls -l    # 命令 + 选项
ls -l /home  # 命令 + 选项 + 参数
```
