# 第 3 章：用户与权限管理

## 3.1 为什么需要用户和权限？

Linux 是一个**多用户**操作系统，多个用户可以同时使用同一台机器。

想一想：
- 服务器上 100 个用户，每个人都有自己的文件
- 不能让 A 看到 B 的私人文件
- 不能让普通用户修改系统配置
- 不能让用户删别人的文件

解决方案：**用户 + 权限**。

## 3.2 ⚡ Linux 的用户模型

### 用户的本质

用户其实就是一个**数字**（UID, User ID）：

- `root` → UID = 0（超级用户，上帝）
- 系统用户 → UID = 1~999（用于运行服务）
- 普通用户 → UID = 1000+（我们）

### 用户信息存在哪里？

```bash
# 用户账户信息
cat /etc/passwd

# 输出示例：
root:x:0:0:root:/root:/bin/bash
alice:x:1000:1000:Alice,,,:/home/alice:/bin/bash
```

**每行格式**（7 个字段，用 `:` 分隔）：
```
用户名:密码占位符:UID:GID:描述信息:家目录:默认Shell
```

```bash
# 密码（加密后）存在这里
sudo cat /etc/shadow

# 输出示例：
root:$6$xyz...:18837:0:99999:7:::
alice:$6$abc...:18837:0:99999:7:::
```

**/etc/shadow 格式**：
```
用户名:加密密码:最后修改日:最小天数:最大天数:警告天数:过期天数:过期日期:保留
```

```bash
# 组信息
cat /etc/group

# 输出示例：
root:x:0:
sudo:x:27:alice,bob
alice:x:1000:
```

### ⚡ 用户与组的关系

```
用户 alice (UID=1000)
    属于：alice 组（主要组）、sudo 组（附加组）
    
用户 bob (UID=1001)
    属于：bob 组（主要组）、sudo 组（附加组）

文件 /etc/shadow
    所有者：root
    所属组：shadow
    权限：-rw-r----- (所有者读写，组读，其他人无)
```

## 3.3 ⚡ 文件权限（rwx）

### 查看权限

```bash
ls -l file.txt
-rw-r--r-- 1 alice alice 1024 Jul 7 10:00 file.txt
```

### 权限的三组九位

```
所有者(u) 组(g) 其他人(o)
  r w x    r w x    r w x
  ↑ ↑ ↑    ↑ ↑ ↑    ↑ ↑ ↑
  读 写 执行  读 写 执行  读 写 执行
```

### 权限的含义

**对文件**：
- `r` (4) — 读：查看文件内容（cat, less）
- `w` (2) — 写：修改文件内容（vim, echo >）
- `x` (1) — 执行：运行文件（./program）

**对目录**：
- `r` (4) — 读：列出目录内容（ls）
- `w` (2) — 写：在目录中创建/删除文件（touch, rm, mkdir）
- `x` (1) — 执行：进入目录（cd）

> ⚡ **关键理解**：目录的 x 权限允许你"穿过"它。只有 r 没有 x，可以 ls 但无法 cd 进去。

### 数字表示法

```
r = 4, w = 2, x = 1
rwx = 4+2+1 = 7
rw- = 4+2+0 = 6
r-- = 4+0+0 = 4
-wx = 0+2+1 = 3

chmod 755 file    # rwxr-xr-x
chmod 644 file    # rw-r--r--
chmod 600 file    # rw-------
chmod 777 file    # rwxrwxrwx（危险，任何时候都不要用）
```

## 3.4 chmod — 修改权限

### 数字方式

```bash
chmod 755 script.sh     # rwxr-xr-x
chmod 644 file.txt      # rw-r--r--
chmod 700 private/      # rwx------
```

### 符号方式

```bash
u = user (所有者)
g = group (组)
o = other (其他人)
a = all (所有人)
+ = 添加权限
- = 移除权限
= = 设置权限

chmod u+x script.sh     # 给所有者加执行权限
chmod g-w file.txt      # 给组移除写权限
chmod o+r file.txt      # 给其他人加读权限
chmod a+x script.sh     # 给所有人加执行权限
chmod u=rwx,go=rx file  # 所有者全部，组和其他为读+执行
```

### 实用场景

```bash
# 脚本必须要有执行权限才能运行
chmod +x script.sh

# 私钥必须只能自己读（否则 SSH 会拒绝）
chmod 600 ~/.ssh/id_rsa

# 网站文件
chmod 644 *.html        # 文件
chmod 755 */            # 目录

# 共享文件夹
chmod 775 shared/       # 组内可以写
```

## 3.5 chown / chgrp — 修改所有者和组

```bash
# 修改所有者
sudo chown alice file.txt

# 修改所有者和组
sudo chown alice:staff file.txt

# 只修改组
sudo chgrp staff file.txt

# 递归修改
sudo chown -R alice:staff directory/

# 只修改组（保持所有者不变）
sudo chown :staff file.txt
```

## 3.6 umask — 默认权限的"遮罩"

每当你创建文件或目录时，系统会默认分配权限：
- 文件默认：666 (rw-rw-rw-)
- 目录默认：777 (rwxrwxrwx)

**umask 从默认值中"扣掉"权限**：
```bash
umask          # 查看当前 umask（通常是 022）
```

umask = 022 时：
```
文件：666 - 022 = 644 (rw-r--r--)
目录：777 - 022 = 755 (rwxr-xr-x)
```

**计算方式**：默认权限 - umask = 实际权限

```bash
umask 077      # 临时修改（文件变成 600，目录变成 700）
umask 002      # 组用户可以写（适合协作）

# 永久修改（写入配置文件）
echo "umask 027" >> ~/.bashrc
```

## 3.7 ⚡ 特殊权限

### SUID (Set User ID) — 4xxx

当可执行文件设置 SUID 时，**谁运行它，它就拥有文件所有者的权限**。

```bash
# 典型例子：passwd
ls -l /usr/bin/passwd
-rwsr-xr-x 1 root root 59976 ... /usr/bin/passwd
#   ↑ s 代替了 x
```

**原理**：
```
普通用户 alice
    ↓ 运行 passwd
    ↓ passwd 有 SUID，所有者是 root
    ↓ 所以 passwd 以 root 身份运行
    ↓ 可以修改 /etc/shadow
    ↓ 修改自己的密码成功
```

```bash
# 设置 SUID
chmod u+s program
chmod 4755 program    # 4 = SUID
```

> ⚠️ SUID 很危险。一个有 SUID 的 Shell 能让任何人获得 root 权限。

### SGID (Set Group ID) — 2xxx

- 文件：以文件所属组的身份运行
- 目录：在该目录下创建的文件，组自动继承目录的组

```bash
chmod g+s directory
chmod 2755 directory   # 2 = SGID
```

**SGID 目录的实用场景**：
```bash
# 创建共享目录，所有成员都能读写
sudo mkdir /shared
sudo chgrp staff /shared
sudo chmod 2775 /shared
# 以后 staff 组的成员在此创建文件，组自动为 staff
```

### Sticky Bit — 1xxx

**目录**：只有文件的所有者才能删除自己的文件（典型：/tmp）

```bash
ls -ld /tmp
drwxrwxrwt 10 root root 4096 ... /tmp
#        ↑ t 代替了 x

# 设置
chmod o+t directory
chmod 1777 directory   # 1 = Sticky Bit
```

## 3.8 sudo — 借权限

普通用户执行管理员命令：

```bash
sudo apt update           # 以 root 更新软件源
sudo -i                   # 切换到 root Shell
sudo -u alice command     # 以 alice 身份执行
sudo -l                   # 查看自己有哪些 sudo 权限
```

### sudo 的配置（/etc/sudoers）

```bash
sudo visudo               # 用安全的方式编辑 sudoers
```

配置格式：
```
用户名  主机名=(可切换的用户:可切换的组)  命令
alice   ALL=(ALL:ALL) ALL                 # alice 可以做任何事情
bob     ALL=(ALL) NOPASSWD: /usr/bin/apt  # bob 可以无密码运行 apt
%sudo   ALL=(ALL:ALL) ALL                 # sudo 组的所有成员
```

## 3.9 用户管理命令

```bash
# 创建用户
sudo useradd -m -s /bin/bash alice    # -m 创建家目录，-s 指定 Shell

# 删除用户
sudo userdel -r alice                 # -r 同时删除家目录

# 修改用户
sudo usermod -aG sudo alice           # 将 alice 加入 sudo 组
sudo usermod -L alice                 # 锁定用户（禁止登录）

# 修改密码
passwd                                # 改自己的密码
sudo passwd alice                     # root 改别人的密码

# 查看用户信息
id alice                              # 查看 UID、GID、所属组
who                                   # 当前谁登录了
w                                     # 更详细的登录信息
whoami                                # 我是谁
```

## 3.10 用户权限的综合例子

```bash
# 场景：建立一个团队共享目录

# 1. 创建团队组
sudo groupadd devteam

# 2. 添加成员
sudo usermod -aG devteam alice
sudo usermod -aG devteam bob

# 3. 创建共享目录
sudo mkdir -p /srv/devteam

# 4. 设置组和权限
sudo chgrp devteam /srv/devteam
sudo chmod 2775 /srv/devteam    # rwxrwsr-x（SGID）

# 5. 现在 alice 创建的文件
touch /srv/devteam/alice_file
ls -l /srv/devteam/alice_file
# -rw-r--r-- 1 alice devteam ... alice_file  ← 组自动为 devteam
```
