RAG 检索增强生成技术详解

检索增强生成（Retrieval-Augmented Generation，简称 RAG）是 2020 年由 Facebook AI Research（现 Meta AI）提出的一种结合信息检索与文本生成的技术范式。其核心思想是在 LLM 生成回答之前，先从外部知识库中检索与用户问题相关的文档片段，将检索结果作为上下文注入到提示词中，让 LLM 基于这些参考资料而非纯粹依赖训练时记忆的参数化知识来生成答案。这一机制有效缓解了 LLM 的知识截断问题（模型训练数据的知识截止日期）、幻觉问题（模型编造不存在的事实）和领域知识不足问题。

一、RAG 的核心流程
标准的 RAG 流程分为离线阶段和在线阶段。离线阶段（Indexing）：将知识库文档通过文档加载器读入 → 文本分割器切分为语义块（chunk）→ 嵌入模型将文本块转为稠密向量 → 向量存入向量数据库并建立索引。在线阶段（Retrieval + Generation）：用户输入问题 → 问题同样通过嵌入模型转为查询向量 → 在向量数据库中执行近似最近邻（ANN）搜索，返回最相似的 top-k 个文档块 → 将这些检索到的文档块与用户问题一起填充到 LLM 提示词模板中 → LLM 基于参考资料生成回答。

二、混合检索：稠密向量与稀疏向量的互补
这是提升 RAG 检索质量的关键技术。稠密检索（Dense Retrieval）使用深度学习嵌入模型（如 text-embedding-v4、BGE-M3）将文本编码为固定维度的浮点数向量，通过向量相似度（余弦相似度或内积）衡量语义相关性。稠密向量的优势在于能够捕捉语义层面的关联——例如"编程"和"写代码"在稠密向量空间中距离很近，即使字面完全不同。稀疏检索（Sparse Retrieval）则基于词汇级别的匹配，如 BM25 算法或 BGE-M3 的稀疏权重输出，将文本表示为词汇表中每个词的权重向量。稀疏向量的优势在于精确的关键词匹配——对于专有名词、技术术语、缩写等，稀疏检索能精准定位包含这些词的文档。混合检索（Hybrid Search）同时执行稠密和稀疏两路检索，将结果通过融合算法合并，兼得两者的优势。

三、RRF 融合与重排序
倒数秩融合（Reciprocal Rank Fusion，RRF）是最常用的混合检索融合算法。其思想是：文档在多路检索中的排名比绝对分数更可靠。RRF 对每个文档在两路结果中的排名取倒数加权：score = 1/(k + rank + 1)，其中 k 是衰减系数（通常取 60）。如果同一文档同时出现在稠密和稀疏两路的高排名位置，它的 RRF 分数会累加，从而获得更高的融合排名。RRF 不需要原始检索分数（不需要分数校准），对任意检索器都适用。融合后的结果通常有 10-20 篇候选文档。接下来用交叉编码器（Cross-Encoder）进行重排序（Reranking）——交叉编码器将查询和文档拼接后一次性输入 Transformer 模型，输出一个精确的相关性分数，这比向量相似度（双编码器分别编码再点积）更准确，因为模型能看到查询和文档的完整交互关系。BGE-Reranker-v2-M3 是常用的中文重排序模型。重排序后取 top 文档作为最终检索结果。

四、评估指标
RAG 系统的评估通常使用 RAGAS 框架。忠实度（Faithfulness）衡量生成答案中的每句话是否都能在检索到的文档中找到依据，理想值为 1.0。答案相关度（Answer Relevancy）评估回答是否紧扣问题。上下文召回率（Context Recall）衡量检索到的文档覆盖了多少应该被找到的内容。上下文精确率（Context Precision）衡量检索到的文档中有多少是真正相关的。评估需要标注数据集（问题 + 参考答案 + 相关文档），但构建成本高，研究者也在探索基于 LLM 的无参考自动评估方法。

五、高级 RAG 架构
朴素 RAG（单次检索加单次生成）在复杂场景下有明显的局限性：检索质量差时答案必然差；无法处理需要多步推理的问题；不知道何时该检索、何时直接用模型知识回答。Agentic RAG 引入了智能体决策机制——LLM Agent 评估检索文档的相关性，如果文档不够好则改写查询重新检索，最多尝试 N 次。Self-RAG 让模型在生成过程中自省，判断是否有事实依据。Corrective RAG（CRAG）对检索结果进行后处理过滤。Adaptive RAG 根据问题的复杂度自适应选择检索策略：简单问题直接回答，中等复杂度单步检索，复杂问题多步分解检索。LangGraph 是实现 Agentic RAG 的理想框架，其有向图结构天然支持条件分支和循环。
