大语言模型应用开发实践

大语言模型（Large Language Model，LLM）是指基于 Transformer 架构、通过海量文本数据预训练得到的超大规模神经网络模型，参数量通常达到数十亿到数千亿级别。以 OpenAI 的 GPT-4o、Anthropic 的 Claude、Google 的 Gemini、阿里云的 Qwen-Max 等为代表的 LLM 展现出强大的语言理解、推理和生成能力，正在重塑软件开发的范式。

一、LLM 的核心能力与局限
LLM 具备以下核心能力：文本生成（撰写文章、邮件、报告等各类内容）、语言理解与推理（阅读理解、逻辑推理、因果关系分析）、知识问答（基于预训练过程中学习的参数化知识进行回答）、代码生成与调试（根据自然语言描述生成 Python、JavaScript 等代码）、翻译与摘要（跨语言翻译和长文本摘要）。然而 LLM 也存在明显局限：知识截断问题（模型训练完成后无法获取新知识，知识截止于训练数据的日期）；幻觉（Hallucination）问题（模型可能在不确定时编造出看似合理但实际虚构的内容）；缺乏领域深度（通用模型在垂直领域如法律、医疗、金融方面可能缺乏足够的专业知识）；上下文窗口限制（单次对话或文档的长度有限，超过限制后前面的内容会被遗忘，如 GPT-4o 为 128K tokens）。

二、提示词工程（Prompt Engineering）
提示词是调用 LLM 的关键接口。设计良好的提示词能大幅提升输出质量。基本策略包括：角色设定（给 LLM 分配一个具体角色，如"你是一位资深 Python 开发工程师"）；输出格式约束（要求返回 JSON、Markdown 表格、代码块等特定格式）；分步指令（将复杂任务拆解为清晰的步骤序列）；少样本学习（提供 2-5 个输入-输出示例引导模型学习模式）；思维链（Chain-of-Thought）引导模型在回答前先展示推理过程。OpenAI 兼容 API 统一了不同 LLM 提供商的调用方式——只需修改 base_url、api_key 和 model 三个参数即可切换模型。阿里云百炼 DashScope 的兼容模式正是采用了这一规范，让国产模型可以无缝接入基于 LangChain 或 OpenAI SDK 构建的应用生态。

三、RAG 与 LLM 的结合
RAG 通过引入外部知识库弥补了 LLM 的三大短板。准确性问题：RAG 让 LLM 基于检索到的真实资料生成回答，而非依赖可能过时或不准确的训练记忆，显著降低幻觉率。领域性不足：通过将企业文档、专业资料导入向量数据库，LLM 获得垂直领域的专业问答能力。知识更新：知识库可以持续增删更新，无需重新训练模型。RAG 加 LLM 的组合已成为企业级 AI 应用的主流架构。实际部署中需要注意检索质量（检索回来的文档是否相关直接决定回答质量）、上下文窗口管理（检索到的文档块总长度不能超过 LLM 的输入限制）、引用溯源（在回答中标注信息来源以增强可信度）。

四、Agentic RAG
传统 RAG 的一个核心问题是"哑检索"——无论检索结果好坏，系统都会拿着这批文档生成答案。Agentic RAG 赋予 LLM Agent 自主决策权：分析问题意图；决定是调用检索器还是直接回答；对检索结果进行逐篇评分（相关性 1-5）；如果检索不够理想（关联文档少于阈值），改写查询词重新检索；检索满意后生成回答；生成后自省检查是否有无依据的声明。这种 Agentic 模式让系统像一个有自主判断力的研究员，而非被动的信息搬运工。LangGraph 是实现 Agentic RAG 的最佳框架，它以有向图描述 Agent 的决策流，节点和条件边的图结构清晰可审计。

五、LLM API 的兼容模式
DashScope 是阿里云的模型服务平台，提供 Qwen 系列和第三方模型的调用。兼容模式（Compatible Mode）实现了与 OpenAI API 的接口兼容，base_url 设置为 https://dashscope.aliyuncs.com/compatible-mode/v1，即可用标准的 Chat Completions 和 Embeddings 接口调用 Qwen-Max、Qwen-Plus、text-embedding-v4 等模型。LangChain 的 ChatOpenAI 和 OpenAIEmbeddings 类通过修改 base_url 参数即可对接 DashScope。兼容模式下的嵌入 API 支持 dimensions 参数自定义输出维度，但需要注意 batch size 限制——text-embedding-v4 每批最多 10 条文本，超过会返回 400 错误，需在 LangChain 的 OpenAIEmbeddings 中设置 chunk_size=10。另外 check_embedding_ctx_length=False 可以禁用 LangChain 默认的 token 预处理，避免与 DashScope 的 input 格式校验冲突。
