MySQL 数据库原理与性能优化

MySQL 是全球最流行的开源关系型数据库管理系统（RDBMS），由瑞典 MySQL AB 公司开发，2008 年被 Sun Microsystems 收购，2010 年随 Sun 并入 Oracle。MySQL 以其高性能、高可靠性和易用性广泛应用于互联网公司的核心业务系统。

一、架构概览
MySQL 采用分层架构设计。最上层为连接层，负责客户端连接管理、身份认证和线程复用。中间层为服务层，包含查询缓存（8.0 已移除）、SQL 解析器、查询优化器、执行引擎等核心组件。最下层为存储引擎层，通过可插拔架构支持多种存储引擎。查询优化器负责生成执行计划，包括选择最优的索引使用策略、决定表的连接顺序、评估全表扫描与索引扫描的成本。执行计划可通过 EXPLAIN 命令查看，重点关注 type（访问类型：ALL 全表扫描最差、index 索引全扫描、range 索引范围扫描、ref 非唯一索引查找、eq_ref 唯一索引查找、const 主键常量查找最佳）、key（实际使用的索引）、rows（预估扫描行数）、Extra（Using index 覆盖索引、Using filesort 需要额外排序、Using temporary 需要临时表）。

二、存储引擎
InnoDB 是 MySQL 5.5+ 的默认存储引擎，支持事务（ACID）、行级锁、外键约束、崩溃恢复。它使用聚集索引（Clustered Index）组织数据——主键索引的叶子节点直接存储整行数据，因此通过主键查询速度最快。二级索引（Secondary Index）的叶子节点存储主键值，查询需回表（通过主键再到聚集索引中查找完整行）。MyISAM 引擎不支持事务，使用表级锁，适合读多写少的场景，全文索引功能在早期版本中优于 InnoDB。Memory 引擎将数据存储在内存中，重启后数据丢失，适合临时表和缓存场景。MySQL 8.0 引入了原子 DDL、窗口函数、CTE（公共表表达式）、不可见索引、降序索引、资源组管理等重要新特性。

三、索引原理与优化
索引（Index）是数据库性能优化的核心手段，可类比为书籍的目录——通过预先建立的数据结构快速定位数据，避免逐行扫描全表。MySQL InnoDB 的索引底层采用 B+树（B-Plus Tree）数据结构。B+树是一种多路平衡搜索树，所有数据记录存储在叶子节点，且叶子节点通过指针形成有序双向链表。非叶子节点仅存储键值和子节点指针，不存储数据。每次磁盘 I/O 读取一个节点（通常 16KB），B+树通过增大每个节点的分支数（扇出度），将树的高度控制得很低——百万级数据表通常只需 2-3 层即可定位数据。与 B 树相比，B+树将所有数据集中在叶子节点，查询的时间复杂度稳定为 O(log n)，非常适合范围查询（range scan）和排序操作（ORDER BY）。

创建索引需遵循最佳实践：为 WHERE、JOIN、ORDER BY 中频繁使用的列创建索引。复合索引遵循最左前缀原则——例如对 (a, b, c) 建立联合索引，查询条件包含 a → 可用索引，包含 a 和 b → 可用索引，只包含 b 和 c → 不可用索引。索引并非越多越好——每次 INSERT、UPDATE、DELETE 都需要同时维护索引，过多的索引会严重影响写入性能。使用覆盖索引（Covering Index）避免回表——当查询所需的列全部包含在索引中时，直接从索引获取数据，无需访问聚集索引。慢查询日志（slow query log）记录执行时间超过 long_query_time 的 SQL，是定位性能瓶颈的重要工具。

四、事务与锁
事务具有 ACID 四大特性：原子性（Atomicity，Undo Log 回滚保证）、一致性（Consistency，由其他三个特性共同保证）、隔离性（Isolation，锁和 MVCC 实现）、持久性（Durability，Redo Log 崩溃恢复保证）。InnoDB 支持四种隔离级别：READ UNCOMMITTED（读未提交）、READ COMMITTED（读已提交，每次查询生成新快照）、REPEATABLE READ（可重复读，MySQL 默认级别，同一事务内查询结果一致）、SERIALIZABLE（串行化，所有读加共享锁）。InnoDB 的行级锁包括共享锁（S Lock，允许读禁止写）和排他锁（X Lock，禁止读写），通过索引实现——WHERE 条件不包含索引时会退化为表级锁。间隙锁（Gap Lock）锁定索引记录之间的间隙，防止幻读（Phantom Read）。

五、高可用与复制
MySQL 主从复制（Replication）基于二进制日志（binlog），支持异步复制（默认）、半同步复制（至少一个从库确认）、组复制（Group Replication，基于 Paxos 协议的强一致性）。GTID（全局事务标识符）简化了复制拓扑的配置和故障切换。读写分离（Read/Write Splitting）是常见的扩展方案，主库处理写入，从库分摊查询负载，应用层通过中间件如 ProxySQL 或 MySQL Router 实现透明路由。MHA（Master High Availability）和 Orchestrator 提供了自动故障检测和主从切换能力。
